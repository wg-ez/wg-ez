# AGENTS.md — wg-ez

Rust reimplementation of wg-easy: a WireGuard server + web UI + offline CLI shipped
as one static musl binary. Shared logic lives in the `wgez` lib (`src/lib.rs`); the
`wg-ez` bin (`src/main.rs`) only routes `wg-ez serve` and `wg-ez cli ...`.
Source comments and log/output strings are mostly French — match the local style.

## Build & run — Docker only

The host provides **only Docker + Compose**. There is no host cargo/rust/node.

- Prod: `docker compose up -d` runs the published image
  (`docker-compose.yml`). Dev: `docker compose -f docker-compose.dev.yml
  up --build` runs the gates (fmt+clippy+test+htmx) then builds and starts
  the server from sources; `--watch` adds the dev loop (sync `static/`,
  rebuild on `src|templates|locales` change).
- Settings default to working values; overrides go in an optional
  `environment:` block (see README), no `.env` file. The UI port is the left
  side of the ports mapping.
  For plain-HTTP access set `INSECURE=true`; otherwise the `Secure` session cookie
  is refused by the browser and login appears to succeed then bounces to `/login`.
- **No command writes into the source tree.** Builds, tests, lint, CSS and the HTTP
  audit all run inside Docker build stages (`docker build --target …`) or dev
  compose services; the cargo cache lives in a BuildKit cache mount, never in
  the repo. The host only holds the git-tracked files (no `target/`, no
  `node_modules/`).
- `static/css/app.css` is generated by the `css` Dockerfile stage (Tailwind via
  `@tailwindcss/cli`) and reused by the quality stages and the musl build; the
  committed copy exists only so `build.rs` (which fails if it is missing) succeeds
  when a stage does not wire the `css` stage. `docker build --target css .`
  validates/regenerates it **inside the image** — nothing lands on the host.
  After editing `input.css`, rebuild the image (`docker build -t wg-ez:latest .`
  or the dev compose `up --build`) to refresh `app.css`.
- The `htmx` dev compose service verifies that the vendored
  `static/vendor/htmx.min.js` matches the pinned version and SHA-256; it
  downloads and hashes inside a disposable container and never writes to the host.

## Quality gates

- `docker compose -f docker-compose.dev.yml up --build fmt clippy test`
  (or the full dev `up --build`, which gates `wg-ez` on them). Run before finishing.
  Warnings are errors: `cargo fmt --check` and
  `cargo clippy --all-targets --all-features -- -D warnings`.
- Each gate is a Dockerfile stage (`fmt`/`clippy`/`test`) run via
  `docker build --target <stage> .`; BuildKit caches the compile in a cache mount,
  so a re-run only re-executes the check. Tests run in a **glibc `rust:bookworm`**
  stage, never in the musl build, and are unprivileged — system calls are faked via
  `MockRunner`/`NoopRunner`, so no root, no real `wg`/iptables, no kernel.
- Single test (same `test` stage, filter injected as a build arg):
  `docker build --target test --build-arg TEST_FILTER=<substring> .`
- The `audit` dev compose service runs `scripts/audit.sh` from the `audit`
  image (bash+curl, `--network host`) against a live server (start the dev
  compose first): 270 HTTP checks. It
  hard-fails if the check total drifts from 270 — update the total and per-file
  counts in `scripts/audit.sh` when adding checks. Full QA = gates + live
  server + audit.

## Architecture

- `serve` freezes config at boot, migrates the DB, applies `INIT_*`, mounts WireGuard
  (`down`+`up`), serves HTTP, runs a 60 s cron, then cleanly `wg-quick down`s on stop.
- `src/tunnel/` is the **only** module allowed to touch the kernel. Every config
  mutation runs a full `Tunnel::apply`: render → write `<iface>.conf` mode `0600` →
  `wg syncconf` (hot; **never** `wg-quick up`) → firewall rebuild. Settings that
  cannot be hot-applied (MTU, Table, Address/CIDR, Pre/Post hooks) require
  `Tunnel::restart` (`down`+`up`, briefly drops tunnels). `wg-quick up` only runs at
  boot, restart, and via the admin Restart button.
- All system commands go through the `Runner` trait (`src/wg/runner.rs`):
  `SystemRunner` (prod), `MockRunner`/`SharedRunner` (tests), `NoopRunner`.
  `WG_EXECUTABLE` (default `wg`) selects the binary; non-Linux is a stub.
- DB is `rusqlite` (bundled SQLite — the **only** allowed C). Migrations are numbered
  SQL files in `src/migrations/`, applied in order via `PRAGMA user_version`. To add
  one: create the `.sql` file **and** register it in the `MIGRATIONS` array in
  `src/db.rs`. WAL + `foreign_keys=ON`. Dates are canonical UTC ISO-8601 whole seconds
  (`...Z`) so lexicographic comparison is chronological; booleans are INTEGER 0/1.
- Web stack: axum on a **single-thread `current_thread`** tokio runtime. Every blocking
  call (sqlite, argon2, `wg`) must run inside `spawn_blocking` — see
  `SqliteBackend::with_db`. Routes: all API under `/api`; public `/cnf/*` and
  `/metrics/*`; UI pages at `/`, `/clients/{id}`, `/me`, `/login`, `/admin`, `/setup/*`.
- Handlers are thin; real logic lives in `src/web/backend/*` behind the `Backend` trait.
  `TestBackend` (`src/web/router/tests.rs`) is injected for router tests.
- Auth: `wg-ez` cookie or `Authorization: Basic` (Basic refused when 2FA is active).
  Only the SHA-256 of a 256-bit session token is stored. Rate limits are in-memory.
  CSRF is enforced via `Sec-Fetch-Site`.
- i18n is EN + FR only; `locales/en.json` is canonical. Templates compile in via
  askama (`askama.toml` points at `templates/`).

## Non-negotiable conventions

- `#![forbid(unsafe_code)]` everywhere; no `unwrap`/`expect` on user-reachable paths —
  fallible functions return `Result`. Release uses `panic = "abort"` (a panic kills the
  process), so test route guards through the **real axum router**, never by calling
  handlers directly.
- No ORM, no concatenated SQL: parameterized `rusqlite` only.
- In a patch, `null` means **inheritance** (fall back to the global default of the same
  family), never the same as `[]`.
- Address families are governed solely by `IP_MODE=auto|ipv4|ipv6|both`. A disabled
  family keeps its DB values but is omitted from `.conf` and firewall. Allocation:
  server = network+1, clients = network+2..end-1; a full pool is an explicit error.
- Every client/admin `POST|DELETE` must run `apply_tunnel` **except**
  `POST /api/client/:id/generateOneTimeLink` (the one mutation with no kernel effect).
  New mutating routes that change config must call it.
- CSP is `script-src 'self'` with zero inline script/style; all JS lives in
  `static/js/app.js`. Don't add inline handlers or styles.
- `PASSWORD`/`PASSWORD_HASH` are legacy: setting them must fail boot with a v14→v15
  migration pointer. `EXPERIMENTAL_AWG`, `OVERRIDE_AUTO_AWG`, `OAUTH_*` are ignored.
- Dependencies are latest-only, no pins. Do not add `openssl`/`native-tls`/`rustls`/
  `reqwest`, `chrono` (use `time`), `regex`, `uuid`, `diesel`/`sea-orm`, `tokio-util`,
  `totp-rs`, or `tower_governor` (the last two are hand-rolled). Justify any new dep.

## Gotchas

- A fresh musl build re-gzips all of `static/` in `build.rs`, but only `app.css` is
  tracked for `rerun-if-changed`; editing `app.js`/vendor does not retrigger it.
- `docker-compose.yml` is production-only and minimal (published image, no
  build, no watch, no `environment:` — everything runs on defaults).
  Dev build + `develop.watch` live in the standalone `docker-compose.dev.yml`:
  `docker compose -f docker-compose.dev.yml up --build --watch`.
- API paths are strict: a trailing slash is a 404; only `//` doubling 308-redirects.
  UI pages keep the trailing-slash redirect.
- UI dev loop: `docker compose -f docker-compose.dev.yml up --build --watch`
  (syncs `static/js|vendor|img`, rebuilds on
  `src|templates|locales|static/css/input.css` changes). `app.css` is never synced
  from the host — it is regenerated inside the image on rebuild, so edit
  `input.css` and let Compose rebuild (no live Tailwind watch, by design,
  to keep the host write-free).
